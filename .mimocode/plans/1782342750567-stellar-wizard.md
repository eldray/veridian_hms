# RBAC & Audit Attribution Plan

## Overview
Two-part implementation:
1. **Role-based page/nav access** — define exactly what each role can see and do
2. **Inline audit attribution** — every action stamps user + timestamp, visible in UI

- **Admin**: All tabs (Company, Users, Service Catalog, Medical Services, G-DRG, NHIS, Appearance, Backup)
- **Doctor/Nurse/Midwife**: Appearance tab only
- **Other roles**: Access restricted message

```ts
const isAdmin = hasRole(['admin']);
const isClinical = hasRole(['doctor', 'nurse', 'midwife']);

// Filter tabs based on role
const visibleTabs = mainTabs.filter(tab => {
  if (isAdmin) return true;
  if (isClinical && tab.id === 'appearance') return true;
  return false;
});

if (!isAdmin && !isClinical) {
  return <AccessRestricted />;
}
```

### 2.2 Pattern for each route file

```ts
// Example: LabTestRoutes.ts
router.use(protect);

// Read routes - broader access
router.get('/', requireRole(['admin', 'doctor', 'lab_tech']), controller.getAll);
router.get('/:id', requireRole(['admin', 'doctor', 'lab_tech']), controller.getById);

// Write routes - restricted
router.post('/', requireRole(['admin', 'lab_tech', 'doctor']), controller.create);
router.put('/:id', requireRole(['admin', 'lab_tech']), controller.update);
```

## Phase 3: Inline Audit Attribution — Backend

### 3.1 Ensure all services capture userId

Audit each module's service to verify `createdById` / `performedById` / `dispensedById` etc. are passed from `req.user.id` in controllers. Key modules to check:

- **Encounter/Attendance**: `createdById` — verify controller passes `req.user.id`
- **Lab Tests**: `createdById`, `performedById`, `verifiedById` — verify all three are captured
- **Scans**: `createdById`, `performedById`, `verifiedById`
- **Procedures**: `createdById`, `performedById`
- **Medications**: `prescribedById`, `dispensedById`, `administeredById`
- **Payments**: `receivedById` (Payment model has `receivedBy` relation)
- **Vitals**: `recordedById` (Vitals model has relation to User)
- **Appointments**: `createdById`
- **Admissions**: verify `admittedById` or similar
- **Bills**: `createdById`
- **Requisitions**: `requestedById`, `approvedById`, `fulfilledById`
- **Stock Transfers**: `requestedById`, `approvedById`
- **Insurance Claims**: `createdById`
- **Referrals**: `referredById` or similar

For any module missing user attribution:
1. Add field to Prisma schema (e.g., `performedById String?`)
2. Add relation: `performedBy User? @relation(fields: [performedById], references: [id])`
3. Run `npx prisma migrate dev`
4. Update service to accept and store userId
5. Update controller to pass `req.user.id`

### 3.2 Ensure controllers pass userId from auth

Pattern — every controller method should extract user from request:

```ts
const userId = (req as AuthRequest).user?.id;
// Then pass to service:
await this.service.create(data, userId);
```

## Phase 4: Inline Audit Attribution — Frontend

### 4.1 Create reusable `AuditInfo` component

**New file**: `frontend/src/components/AuditInfo.tsx`

```tsx
interface AuditInfoProps {
  action: string;           // e.g., "Prescribed", "Dispensed", "Recorded"
  userName?: string;        // e.g., "Dr. Smith"
  timestamp?: string | Date; // e.g., "2025-01-15T10:30:00Z"
  className?: string;
}

export function AuditInfo({ action, userName, timestamp, className }: AuditInfoProps) {
  if (!userName && !timestamp) return null;
  return (
    <div className={`flex items-center gap-1.5 text-[10px] text-[var(--text-tertiary)] ${className}`}>
      <span>{action} by <strong>{userName || 'Unknown'}</strong></span>
      {timestamp && (
        <>
          <span>·</span>
          <span>{formatTimestamp(timestamp)}</span>
        </>
      )}
    </div>
  );
}
```
